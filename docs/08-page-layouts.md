# Page layouts

- Status: Implemented
- Audience: Designers, content owners, developers and QA
- Owner: Design-system maintainer
- Last updated: 2026-08-30

## Shared desktop frame

A sticky compact header sits above a maximum 74rem content shell. Major sections use 5–8.5rem vertical spacing. Page heroes constrain copy to approximately 60rem. Footer content forms three clear columns. The approved design canvases are compressed showcases; they are not a spacing template.

## Shared mobile frame

Below 46rem, all principal layouts become one column, the abstract hero moves after the copy, navigation uses a native disclosure control, cards stack, and section spacing becomes about 4.5rem. Copy and calls to action appear before decoration.

## Page-by-page layout

| Page | Desktop sequence | Mobile adaptation |
|---|---|---|
| Home | Split hero; 4 programme cards; 3 approach cards; daycare split; 4-step rhythm; contact CTA | Hero copy then art; all grids stack |
| About | Page hero; story split; 3 values; narrow team policy; CTA | Story and values become one column |
| Approach | Page hero; 3 principles; practical-life split; narrow family note; CTA | Principles and split stack |
| Programmes | Page hero; 4 equal programme cards; placement split; CTA | Programme cards become a readable sequence |
| Daycare | Page hero; 3 care cards; hours split; question list; CTA | All sections stack; hours stay prominent |
| Admissions | Page hero; 4 visit steps; location/contact split; privacy note | Steps become a vertical process |
| Policy pages | Page hero plus narrow long-form article | Same order with responsive type |
| 404 | Large recovery message and two actions | Actions wrap and remain touch-sized |

## Admin layout

Desktop uses a two-column grid for contact and homepage/SEO, then full-width programme and revision panels. Mobile uses one column. Status updates use a polite live region. Publish, save, preview and restore actions are visually distinct.
